# Phase 0 J8 findings — 2026-10-08

Decision: **PROCEED**

Target: Samsung Galaxy J8 / SM-J810M / Android 10 (API 29)

Candidate commit validated on device: `3059548800269f201daaeaf85e510e8872381b48`

## Capture path

The J8 diagnostic probe initialized:

- source: `VOICE_RECOGNITION`
- configured / actual sample rate: 48,000 Hz
- format: mono PCM16
- route: Android input device type 15, product `SM-J810M`
- attempted configuration recorded by the probe: `VOICE_RECOGNITION@48000:initialized`

The absence of an `UNPROCESSED` attempt means Android did not advertise support for that source under the probe's bounded policy. The fallback order therefore behaved as designed.

## Timing

A completed run captured exactly 480,000 samples at 48,000 Hz, i.e. 10.000 seconds of PCM content.

Observed completion values:

- captured samples: 480,000
- wall/monotonic probe elapsed: about 10.15 seconds
- final AudioTimestamp frame position: 480,960
- timestamp timebase: monotonic

At the instant a probe starts, `AudioRecord.getTimestamp` can initially report unavailable (`-3`). Once the first PCM blocks arrive, monotonic AudioTimestamp becomes available and tracks the captured frame progression. Phase 1 should therefore retain a startup fallback path and distinguish timestamp availability from capture failure.

## Manual stop

Manual stop was exercised successfully.

Observed examples:

- 199,680 samples with a clean `Diagnostic capture stopped by user` completion
- 85,440 samples with the same clean manual-stop outcome

The diagnostic path therefore supports both bounded automatic completion and explicit early termination.

## Digital level behavior

RMS and peak values respond to the acoustic input and remain explicitly labeled dBFS, not SPL.

A quiet/background region was typically around the low −40 dBFS RMS range in the supplied evidence.

Loud transients produced several sample-peak readings at exactly **0.0 dBFS**. This is evidence of digital full-scale contact/clipping in the tested path. It is not a Phase 0 blocker, but Phase 1 must:

- count clipped samples;
- expose a clipping / quality flag;
- preserve clipping state in exported session data;
- avoid treating clipped frames as trustworthy amplitude evidence for calibration or acoustic accuracy.

No SPL claim is made from this probe.

## Processing visibility

The platform reported:

- AEC available: true
- AGC available: false
- NS available: true

These are Android platform-availability indicators only. They do not prove whether vendor-side signal processing is active in the physical microphone path.

## Windows development-path findings

The Phase 0 work also exposed and corrected several Windows bootstrap issues:

- CRLF conversion of `gradlew`;
- Windows Make invoking the Unix wrapper;
- unsupported Java 25 runtime being selected for Gradle 8.13;
- PowerShell `$HOME` name collision;
- PowerShell 5.1 treating `java -version` stderr as an error;
- missing Android SDK discovery;
- wrapper failure exit-code propagation.

The final Windows launcher selects JDK 17 and an Android SDK containing platform 36 without requiring global Java changes.

## Unexercised / non-blocking items

- Permission denial was not re-exercised after permission had already been granted.
- Meter ↔ History switching during an active probe is not evidenced in the supplied log/video set.
- APK SHA256 was not present in the supplied transcript and should be added to the final artifact record when the candidate APK is frozen.

These do not invalidate the capture-path decision.

## Decision rationale

**Proceed to Phase 1.**

The tested J8 path provides:

- stable 48 kHz mono PCM capture;
- coherent sample-count progression;
- monotonic audio timestamps after startup;
- clean automatic completion;
- clean explicit manual stop;
- observable dBFS response;
- a known clipping behavior that can be modeled explicitly.

The remaining uncertainties are Phase 1 concerns: durable session ownership, persistence/recovery, export fixture design, clipping/quality flags, and later reference/calibration work.
